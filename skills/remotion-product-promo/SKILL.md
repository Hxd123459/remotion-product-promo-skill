# Remotion 产品宣传片

目标是让第一次看视频的人看懂：谁遇到什么问题、产品具体做了什么、结果为何更好。画面、操作和声音应共同证明这件事。不要把 Roadbook 的时长、暗色界面、emoji 或无旁白形式当成所有产品的固定模板；沿用用户给定的品牌、参考片和已确认版本。

## 先确认画幅和观看场景

- 用户已指定尺寸、画幅或明确的投放规格时直接遵从。否则在设计封面和排版前，请用户选择竖屏 9:16、横屏 16:9 或两种都要，并了解主要播放平台；不要因为产品是手机应用就自行决定竖屏。等待画幅答复期间可以核查产品与素材，但不要把未确认的画幅当成最终交付规格。
- 两种画幅是两套构图：分别安排文字层级、产品界面占比、图片取景和平台安全区域，分别检查可读性。不能把一版简单拉伸、裁切或加黑边充当另一版。

## 先锁定品牌身份与美术方向

- 在绘制任何 Logo、吉祥物或品牌片尾前，清点当前仓库、Git 历史、配置中的资源地址、产品实拍和用户提供的文件。记录每项素材的来源路径、版本、是否能实际打开，并以可见的原始图像核对。找不到可靠原件时，明确标记缺失并向用户索取；不要根据产品名称自造一个“近似 Logo”放进成片。
- 产品界面优先用真实录屏或截图。需要重绘时，以可核查的界面为准，保留导航、配色、字体、数据层级与关键状态；把演示数据标清。视觉风格可以提升，产品身份与操作不能随意改写。
- 对开放式、要求高质感的宣传片，先确定受众、投放场景、品牌关键词和 1–3 个具体参考；从中提炼字体、色彩、构图、材质、转场和节奏。先做封面／开头、紧接的产品操作、片尾风格帧及一段带声音的短样，把开头和下一镜并排检查后再铺满整片。没有参考时基于产品现有视觉提出明确方向，不用通用手机模型和大字卡反复填满时长。

## 先建立可信的演示依据

1. 读取产品代码、官网演示、真实界面、现有视频及用户反馈，记下角色、任务、操作顺序、关键状态、品牌资产和导出要求。用户指定某个版本为基准时，以它实际使用的场景源码、素材和音轨为准；保留原文件，另存新版本。
2. 列出「用户动作 → 界面响应 → 产品价值」证据链。录制、分享、跟练等不能只用标题或功能列表代替，必须出现可辨认的点击、输入、状态变化和结果。不要凭空添加决定产品价值的功能或步骤。
3. 写一张节拍表：每段的角色、画面焦点、观众应懂的一句话、持续时间、操作事件、音乐段落和音效。根据观众理解所需时间分配镜头，而不是机械地平均分配时长。

常用的情绪曲线是「好奇 → 看懂阻碍 → 阻碍累积 → 短暂停顿与期待 → 产品亮相/音乐高潮 → 掌控感与完成」。按产品和目标观众调整，不必强行加入每个阶段；关键是情绪转折有可见的事件支撑。

## 叙事与构图

- 封面和开场要让观众立刻认出同一支片的品牌、产品或核心任务。选定开场画面前，说明它如何引出紧接的产品镜头，并同时检查故事因果与画面过渡。生活场景或生成图片可以使用，但从摄影画面进入扁平产品界面时，应让同一物件、产品屏幕、构图或连续运动承担转场；只在两边重复一行文案或一个品牌色，不能弥补突兀的硬切。具体失误与改法见 [references/production-patterns.md](references/production-patterns.md)。
- 若另行导出静态封面，从片内的视觉系统和核心承诺提炼，不另起一套主题。按最终发布平台的缩略图尺寸检查产品身份、标题和主体是否一眼可读；横竖版分别设计封面构图。
- 从一个具体任务切入。痛点要让观众看见重复劳动或阻碍逐步加重，给困惑留出停顿；不能在观众尚未理解操作时突然打出抽象结论。情绪可通过操作犹豫、来回切换、角色短句、表情和节奏递进来表达，但每镜头只突出一个信息。
- 若采用痛点先行结构，产品登场前要让困境成立；登场时让画面真的出现产品及其作用。若有音乐高潮，把高潮落在产品已经进入画面之后的关键动作或效果上。随后展示完整的「入口 → 操作 → 反馈 → 完成/分享/使用」链条，并在结尾留出结果和品牌记忆点。
- 多角色流程要标清当前操作者及角色交接。痛点与解决方案尽量复用同一套系统界面、比例、导航和布局，使改善能直接对比。文案靠近正在发生的动作，不要让文字、动画和表情分散在画面各处。
- 用户已认可的镜头、节奏和设计是基线。局部修改时只改相关场景；最终合成要引用最新通过检查的片段，防止把旧问题重新剪回来。

## 把一次操作做成一个同步事件

给每次交互建立同一时间轴上的事件：光标接近并短暂停顿 → 光标尖端落在目标有效区域，优先居中 → 点击脉冲从尖端扩散 → 点击音效响起 → 目标产生按下、选中、输入或成功反馈。目标位置、脉冲原点和音效应从同一个事件时间计算，避免各自写死后错位。改文案或语言后重新核对按钮中心。

可复用的白色光标与轻量音效在 [assets](assets/)；具体实现、音画同步和 Roadbook 案例的教训在 [references/production-patterns.md](references/production-patterns.md)。复制素材到项目后再按品牌调整；素材只是起点，不要求每次照搬。

## 音乐与音效

- 配乐的审美判断需要实际试听，并能说明曲目的来源、使用许可、情绪走向和与画面关键动作的对应关系。当前环境无法听音时，提供同画面的配乐对比短样，请用户试听确认；波形、响度和峰值只能验证技术质量，不能冒充主观试听。简单正弦波、机械循环或临时占位音乐不得作为正式成片的配乐；缺少可用曲目时先交付静音风格样片并说明素材缺口。
- 先试听候选曲的前奏、自然 build/drop、后段及结尾。优先选择音乐本身有清楚层次、能与产品登场时间匹配的曲目；通过剪辑起点对齐高潮。不要为了制造高潮，随意在现有曲目外叠一套不属于它的鼓组。
- 比较多首曲目时，固定画面、音效和大致混音方式，只更换背景曲及其起点，渲染可直接对比的版本；确认选择后再精调混音。
- 背景音乐负责连续节奏，音效只强调有意义的节点：轻点击、柔和的页面切换、通知、分享的低频柔和「咻」、完成反馈。反复出现的切换声尤其要轻，避免刺耳或压过音乐。音量靠实际试听与峰值检查决定，不照抄某一支片的数值。
- 音乐临近结尾自然淡出。分别试听音乐独奏、音效独奏、完整混音；核对授权或用户提供素材的使用范围。

## 制作与验收

- 风格验收看品牌真实性、封面与正文的连续性、辨识度、字体与间距、画面层次、动效理由、界面可信度和音画情绪；技术验收看渲染、时长、帧率与音轨。技术合格不代表视觉合格。逐镜检查是否存在伪造品牌素材、与产品无关的封面、通用占位图形、重复的大字卡或只有标题没有操作的“功能展示”；发现这些问题先改方向，再做完整导出。
- 用可复用的界面组件、设计变量和场景组件维护视觉一致性。动画由帧和时间确定，按场景独立渲染，再按节拍表合成；音效事件表使用全片统一时间基准。若有本地 Remotion 专项技能，按需读取其创作、动画和渲染指南。
- 先渲染能验证方向的短场景，再检查封面缩略图、开头到首个产品镜头的衔接、每次点击前/中/后、角色过渡、产品登场、结尾的静帧与连续播放。核对点击是否真的落在按钮上、文案是否来得及读、UI 是否与真实产品一致、观众能否说出发生了什么。修订后重新检查合成片；交付双画幅时分别验收，不能只检查单个镜头或其中一个画幅。
- 对配音、无旁白、emoji、具体片长或分辨率，遵从用户需求。做中英文等多语言版本时，逐一检查换行、溢出、光标位置、角色文案和音效时间；不要只替换文字。
- 交付源文件和可播放视频。用媒体探测工具确认实际时长、帧率、分辨率、音轨和最后一帧；如果用户要求严格时长，以编码后的文件而非时间轴声明为准。简要说明改动、验证和仍需判断的创意取舍。
