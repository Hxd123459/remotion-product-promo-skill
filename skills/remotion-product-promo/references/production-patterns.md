# 制作模式与 Roadbook 案例

本页提供可借鉴的实现和一次真实迭代的经验；数字是示例，不是所有视频的标准。

## 从 Roadbook 迭代中保留的经验

Roadbook 最终采用「困境 → 流程创建者录制并分享 → 跟练者收到链接并操作 → 品牌收尾」。最初的 5 秒痛点片太快：观众没理解任务，就看到「步骤乱了」的结论。后来的片段让用户在文档与系统间多次切换，并用操作犹豫、简短内心话和 emoji 递进情绪；结论停留更久，产品作用才有可比较的对象。

录制和跟练早期片段的问题是缺少真实动作，或插件 UI 与实际不符。改进后从真实官网、插件状态和现有演示中确认步骤，包括邮箱输入、确认、分享、收到消息、打开链接和跟练进度。角色过渡字幕让观众知道此时是创建者还是跟练者。痛点和产品段沿用同一系统界面。

合成时曾把已修正的「确认按钮点击位置」重新弄错。原因是合成片仍引用旧片段。每个段落应有明确版本来源；改变光标或本地化文字后，要检查所有点击事件及最终合成片。

声音方面，尖锐的切换声和分享声令人不适，额外叠在音乐之外的鼓组与原曲违和。最终保留音乐自身的节奏与高潮，用轻点击、低中频的页面切换声、柔和的分享 whoosh 点缀，高潮与产品出现后的镜头对齐，末尾淡出。这里的 [click.wav](../assets/click.wav)、[page-in.wav](../assets/page-in.wav)、[page-out.wav](../assets/page-out.wav)、[share-soft-whoosh.wav](../assets/share-soft-whoosh.wav) 来自项目内生成的音效；不包含商业背景音乐。

## 可调整的 60 秒节拍表示例

| 时间 | 观众理解的事 | 画面与声音 |
| --- | --- | --- |
| 0–2s | 认识产品 | 简洁 logo 和主张，音乐建立节奏 |
| 2–15s | 一个具体任务为什么费劲 | 同一系统与文档来回切换，困惑递进，轻切换声与点击声 |
| 15–17.5s | 痛点结论 | 保留足够阅读时间，不急于切镜头 |
| 17.5–19s | 操作者变为流程创建者 | 短过渡标清角色；为音乐高潮做准备 |
| 19–36s | 产品如何录制并分享 | 插件真正出现后，音乐进入强段；每步有操作与反馈 |
| 36–37.5s | 操作者变为跟练者 | 短过渡标清角色 |
| 37.5–57.5s | 链接如何变成真实页面引导 | 收到消息、打开链接、逐步操作、完成 |
| 57.5–60s | 记住结果与品牌 | 留白，音乐淡出 |

将这张表改成产品自身的故事和目标时长。关键是理解时间、角色交接和高潮落点，不是复制秒数。

## 点击事件的实现方式

每个点击只定义一次，例如：

```ts
type ClickCue = {
  frame: number;
  target: {x: number; y: number; width: number; height: number};
  sound: 'click' | 'share';
};

const tip = (cue: ClickCue) => ({
  x: cue.target.x + cue.target.width / 2,
  y: cue.target.y + cue.target.height / 2,
});
```

用目标中心得到光标**尖端**位置，再让点击脉冲以此位置扩散。Roadbook 的 SVG 原始路径尖端不在 SVG 盒子的 `(0,0)`：在 32 px 大小时，尖端约距左 3.5 px、距上 0.6 px；案例用约 `translate(-4.5px, -1px)` 对齐。使用其他图标时重新测量热点，不能把图标盒子的中心当成点击点。

Roadbook 的主脉冲约在点击前 1 帧开始，点击后 3 帧扩到最强，约 11 帧收束；第二圈延迟约 4 帧，颜色与选择框一致。这个节奏足够可见又不遮住按钮。让按钮状态与脉冲同帧开始，音效落在实际点击帧；然后抽取「点击前、点击帧、点击后」三张静帧核对。

Remotion 可用 `useCurrentFrame()`、`interpolate()` 或 `spring()` 驱动鼠标路径与脉冲，使用 `Sequence` 分场景、`Audio from={frame}` 放音效。合成片若在音效层使用全片时间，而场景使用局部时间，先把局部帧转换成全片帧；不要靠手工猜秒数。根据场景平移或缩放后的实际渲染坐标检查目标中心。

## 声音与交付检查

挑音乐时先标记原曲的节拍、build、drop 和尾部。若高潮过早或过晚，优先调整音乐起点或画面入场点。音效素材可以从此技能的 `assets/` 复制到项目 `public/`，再用相对 `staticFile()` 路径调用；保留项目自己的音量控制与淡入淡出。页面切换使用低中频且有短衰减的声音；分享 whoosh 用柔和的空气感，避开尖锐的上升啸叫。

最终逐项看：任务是否具体；痛点是否有足够铺垫；角色是否清楚；演示动作是否真实；点击尖端、脉冲、按钮响应和声音是否同拍；音乐高潮是否在产品亮相后；画面是否跨段一致；文案是否读得完；结尾是否留白并淡出。严格片长要求需检查编码后的视频流与音频流，不能只看 Remotion 的 `durationInFrames`。
